# AutoPilot Desktop

Node.js 22 이상과 npm이 필요합니다. 저장소 루트에서 실행하세요.

```sh
npm install
npm start
```

| 명령 | 동작 |
| --- | --- |
| `npm start` | Electron 앱 실행 |
| `npm run dev` | 개발자 도구를 함께 열어 실행 |
| `npm run check` | 메인 프로세스 JavaScript 구문 검사 |
| `npm test` | Electron 창, preload 연결, 로컬 HTML 로드, 번들 엔진 실행(`ELECTRON_RUN_AS_NODE`) 확인 후 자동 종료 (실행 엔진은 시작하지 않음) |
| `npm run test:desktop` | 가짜 CLI로 엔진 제어(시작·종료 신호·강제 종료·로그 해석·다시 연결)와 허용 값 일치, 프로젝트·경로 검사 확인 |
| `npm run build` | Windows x64 앱 폴더 생성 (`dist/win-unpacked/AutoPilot.exe`) |
| `npm run dist` | Windows x64 포터블 EXE 생성 (`dist/AutoPilot-0.1.0-x64.exe`) |

Windows에서 빌드합니다. 최초 설치와 패키징에는 Electron 및 패키징 도구 다운로드를 위한 인터넷 연결이 필요합니다. 배포 EXE는 코드 서명하지 않으므로 Windows에서 게시자 경고가 표시될 수 있습니다.

`desktop/main.cjs`는 앱 창과 보안 설정을, `autopilotRunner.cjs`·`autopilotIpc.cjs`·`projectFiles.cjs`·`preload.cjs`는 엔진 제어와 연결을, `viewFormat.js`·`index.html`·`styles.css`·`renderer.js`는 대시보드 화면을 담당합니다(`viewFormat.js`는 화면에 의존하지 않는 표시용 함수라 `npm run test:desktop`이 따로 검증합니다). 별도 웹 서버나 프론트엔드 빌드 도구는 사용하지 않습니다. 서체는 `desktop/fonts/`의 Pretendard(SIL OFL 1.1, `Pretendard-LICENSE.txt` 동봉)를 앱에 넣어 오프라인에서도 같게 보입니다.

엔진(`autopilot/`)은 앱에 포함됩니다. 앱은 자기 실행 파일을 `ELECTRON_RUN_AS_NODE=1`로 실행해 엔진 스크립트를 자식 프로세스로 띄웁니다(개발 중에는 저장소의 `autopilot/core/autopilot_loop.js`, 패키지에서는 `resources/engine/core/autopilot_loop.js`). 별도 엔진 파일을 연결할 필요가 없습니다.

## 대시보드 사용법

1. 오른쪽 위 설정(톱니) 패널의 **대상 프로젝트**에서 **폴더 선택**으로 대상 프로젝트를 고릅니다. `.git`이 있는 Git 저장소의 루트 폴더만 받습니다. 고르기 전에는 가운데에 안내와 **폴더 선택** 버튼이 표시되고 시작 버튼이 잠깁니다.
2. 버튼 아래 카드 위쪽에 처리할 작업을 한 줄에 하나씩 적고(칸 높이는 고정이고 넘치면 칸 안에서 스크롤), 카드 아래쪽 알약 버튼으로 모델·Effort·개선 정책·종료 시각을 정합니다. 모델·정책·종료 시각은 누르면 고르는 창이 뜨고(종료 시각은 시·분을 올리고 내리거나 1·3·6시간 뒤·기본 07:00을 고름), Effort도 알약을 누르면 뜨는 단계 목록(Low·Medium·High·XHigh·Max)에서 고릅니다. 개선 정책은 설정 패널에서도 고를 수 있습니다. 종료 시각을 비우면 07:00이고, 정책은 자율개선이 기본입니다. **지시개선은 작업이 있어야** 시작합니다.
3. **시작**을 누릅니다. 프로젝트는 고르는 즉시, 나머지(작업·종료 시각·정책·모델·Effort)는 시작할 때 앱 데이터 폴더의 `settings.json`에 저장되어 다음에 복원됩니다. 실행 중 모델·Effort 변경이 엔진에 전달되면 그 값도 저장됩니다.

가운데 버튼 하나가 상태에 따라 바뀝니다.

| 버튼 | 동작 |
| --- | --- |
| 시작 | 엔진을 `--project <프로젝트> --no-open --tasks-file <작업 파일> --policy ... --model ... --effort ...`로 자식 프로세스 실행 (종료 시각을 적었다면 `--end-time`도) |
| 종료 신호 | 실행 중에 표시. 같은 엔진에 `stop`을 전달하고 현재 회차를 마친 뒤 종료 |
| 종료 | 종료 신호를 보낸 뒤 표시. 확인 대화상자를 거쳐 즉시 강제 종료. Windows는 `taskkill /T /F`로 하위 `claude`까지 종료하고, commit 전 변경은 working tree에 남음 |

- 모델(Fable·Opus·Sonnet·Haiku)과 Effort(low~max, 막대 슬라이더)는 실행 중에도 바꿀 수 있습니다. 바꾸면 엔진에 `set`으로 전달되고(Effort는 막대에서 손을 뗄 때 한 번), 진행 중인 회차는 그대로 끝난 뒤 **다음 회차부터** 적용됩니다. 기다리는 값이 있으면 옵션 아래에 "적용 대기"로 표시되고, 회차 기록에는 회차마다 쓴 값이 남습니다. 종료 요청 후에는 바꿀 수 없습니다. 종료 시각·정책·작업은 실행 중에 바꿀 수 없어 잠기고, 작업 칸은 실행 중에는 숨깁니다.
- 가운데에는 최근 로그 4줄이 글자만으로 나타났다가 흐려지며 사라집니다. 최근 로그를 누르거나 설정 패널의 **전체 기록 보기**를 누르면 전체 로그(최근 3000줄 유지, 따라가기·지우기)와 회차 기록이 펼쳐집니다. 회차·남은 시간·종료 예정 시각·회차별 결과는 로그 줄에서 읽습니다.
- 작업은 긴 텍스트라 인자로 넘기지 않고 앱 데이터 폴더의 `tasks.md`에 써서 엔진이 시작할 때 한 번 읽게 합니다. 엔진은 이를 매 회차 프롬프트에 넣습니다.
- 진행 기록(`AUTOPILOT_PROGRESS.md`)은 프로젝트가 아니라 `%APPDATA%\AutoPilot\projects\` 아래에 쌓여 같은 프로젝트의 다음 실행이 이어받습니다. 이어갈 내용을 버리고 새로 시작하려면 설정 패널의 **진행 기록 초기화**를 누릅니다(확인 후 원본을 프로젝트의 `autopilot/progress/`에 보관하고 초기화, 실행 중에는 사용할 수 없음).
- 리포트 HTML은 자동으로 열지 않고 설정 패널의 **리포트 열기**로 엽니다. 시작한 프로젝트의 `autopilot/progress/` 안에 있는 `report_*.html`만 열고, 엔진이 알려준 경로라도 그 밖의 파일은 열지 않습니다.
- 설정 패널 아래에 앱 버전이 표시됩니다.
- 창은 세로형(기본 600×800)이고, 위쪽 헤더는 앱이 직접 그립니다. 헤더를 끌어 창을 옮기고 두 번 클릭하면 최대화하며, 오른쪽 버튼으로 설정·최소화·최대화·닫기를 합니다(닫기는 실행 중이면 아래 확인을 거칩니다). 설정 패널은 Esc나 패널 밖을 눌러 닫습니다.
- 배경은 시각에 따라 바뀌는 수채 하늘입니다. 낮에는 해와 흐르는 구름, 해 뜰 때와 질 때는 노을빛, 밤에는 그날의 달 모양·별·별자리와 가끔 떨어지는 운석이 보이고, UI는 시각과 관계없이 흰색이고, 낮에는 하늘을 깊은 파랑으로 두어 흰 글자가 잘 보입니다. 작업 입력 카드부터는 블러가 점점 짙어집니다. Windows의 동작 줄이기 설정을 켜면 애니메이션이 멈춥니다.
- 앱은 하나만 실행됩니다. 이미 실행 중일 때 다시 켜면 새 창 없이 기존 창이 앞으로 나옵니다.
- 앱을 닫았다 켠 사이에도 엔진이 살아 있어 선택한 프로젝트에서 실행 중이면, 앱을 켜거나 창에 포커스를 줄 때 자동으로 연결합니다. 연결하면 로그 파일을 처음부터 읽어 진행 상황을 복원하고 이어서 따라가며(지난 회차의 시각은 알 수 없습니다), 종료 신호 · 모델 변경 · 강제 종료도 같은 방식으로 쓸 수 있습니다. 연결한 엔진은 앱이 소유하지 않으므로 창을 닫아도 계속 실행되고, 종료 코드는 알 수 없어 로그의 종료 사유만 표시합니다.
- 앱이 시작한 엔진은 창을 닫으면 확인 후 강제 종료합니다.
- VS Code 등이 `ELECTRON_RUN_AS_NODE=1`을 설정한 셸에서는 해제한 뒤 `npm start`·`npm test`를 실행하세요. (앱이 엔진을 띄울 때는 앱이 직접 지정합니다.)

`npm run test:desktop`은 가짜 CLI로 시작·종료 신호·강제 종료·로그 해석을 확인합니다. 엔진 자체의 검증은 루트 README의 `test:cli`를 참고하세요.
