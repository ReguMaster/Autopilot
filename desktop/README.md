# AutoPilot Desktop

Node.js 22 이상과 npm이 필요합니다. 저장소 루트에서 실행하세요.

```sh
npm install
npm start
```

| 명령 | 동작 |
| --- | --- |
| `npm start` | Electron 앱 실행 |
| `npm run dev` | 개발자 도구를 함께 열어 실행 |
| `npm test` | Electron 창, preload 연결, 로컬 HTML 로드, 번들 엔진 실행(`ELECTRON_RUN_AS_NODE`) 확인 후 자동 종료 (실행 엔진은 시작하지 않음) |
| `npm run test:desktop` | 가짜 CLI로 엔진 제어(시작·종료 신호·강제 종료·로그 해석·다시 연결)와 허용 값 일치, 프로젝트·경로 검사, 화면 문장·진행선 계산 확인 |
| `npm run build` | Windows x64 앱 폴더 생성 (`dist/win-unpacked/AutoPilot.exe`) |
| `npm run dist` | Windows x64 설치형 · 포터블 EXE 생성 (`dist/AutoPilot-Setup-<버전>-x64.exe`, `dist/AutoPilot-Portable-<버전>-x64.exe`) |

Windows에서 빌드합니다. 최초 설치와 패키징에는 Electron 및 패키징 도구 다운로드를 위한 인터넷 연결이 필요합니다. 배포 EXE는 코드 서명하지 않으므로 Windows에서 게시자 경고가 표시될 수 있습니다.

`desktop/main.cjs`는 앱 창과 보안 설정을, `systemIntegration.cjs`는 트레이·절전 방지·알림·작업표시줄 진행을, `autopilotRunner.cjs`·`autopilotIpc.cjs`·`projectFiles.cjs`·`preload.cjs`는 엔진 제어와 연결을, `viewFormat.js`·`index.html`·`desktop/ui`는 대시보드 화면을 담당합니다(`viewFormat.js`는 화면에 의존하지 않는 표시용 함수라 `npm run test:desktop`이 따로 검증합니다). 화면은 React 19로 만들어 esbuild가 `desktop/bundle/`로 묶고(`npm run build:ui`), 별도 웹 서버는 두지 않습니다. 서체는 `desktop/fonts/`의 Pretendard(SIL OFL 1.1, `Pretendard-LICENSE.txt` 동봉)를 앱에 넣어 오프라인에서도 같게 보입니다.

엔진(`autopilot/`)은 앱에 포함됩니다. 앱은 자기 실행 파일을 `ELECTRON_RUN_AS_NODE=1`로 실행해 엔진 스크립트를 자식 프로세스로 띄웁니다(개발 중에는 저장소의 `autopilot/core/autopilot_loop.js`, 패키지에서는 `resources/engine/core/autopilot_loop.js`). 별도 엔진 파일을 연결할 필요가 없습니다.

## 대시보드 사용법

1. 오른쪽 위 설정(톱니) 패널의 **대상 프로젝트**에서 **폴더 선택**으로 대상 프로젝트를 고릅니다. `.git`이 있는 Git 저장소의 루트 폴더만 받습니다. 고르기 전에는 작업 칸 위에 안내와 **폴더 선택** 버튼이 표시되고 시작 버튼이 잠깁니다. 고른 프로젝트 이름은 시작 화면 인사말("오늘 밤에는 ○○에 무엇을 해 둘까요?")에 들어갑니다.
2. 화면 아래 카드의 칸에 처리할 작업을 한 줄에 하나씩 적고(칸 높이는 고정이고 넘치면 칸 안에서 스크롤), 카드 아래쪽 알약 버튼으로 모델·Effort·개선 정책·종료 시각을 정합니다. 모델·정책·종료 시각은 누르면 고르는 창이 뜨고(종료 시각은 시·분을 올리고 내리거나 1·3·6시간 뒤·기본 07:00을 고름), Effort도 알약을 누르면 뜨는 단계 목록(Low·Medium·High·XHigh·Max)에서 고릅니다. 개선 정책은 설정 패널에서도 고를 수 있습니다. 종료 시각을 비우면 07:00이고, 정책은 자율개선이 기본입니다. **지시개선은 작업이 있어야** 시작합니다.
3. **시작**을 누릅니다. 프로젝트는 고르는 즉시, 나머지(작업·종료 시각·정책·모델·Effort·사용량 한도 연장)는 시작할 때 그 프로젝트의 설정에 기억되어(전역 값과 다른 것만) 같은 프로젝트를 다시 열면 복원됩니다. 프로젝트에 기억된 값이 없으면 설정 패널의 전역 값을 씁니다(아래 **전역 설정과 프로젝트 설정**). 실행 중 모델·Effort 변경이 엔진에 전달되면 그 값도 기억됩니다.

카드 오른쪽 아래 버튼 하나가 상태에 따라 바뀝니다.

| 버튼 | 동작 |
| --- | --- |
| 시작 | 엔진을 `--project <프로젝트> --no-open --tasks-file <작업 파일> --policy ... --model ... --effort ...`로 자식 프로세스 실행 (종료 시각을 적었다면 `--end-time`, 설정에서 켰다면 `--extend-on-limit`과, 연장 상한을 정했다면 `--max-extend-minutes`도, 커밋 접두어·작업 브랜치를 바꿨다면 `--commit-prefix`·`--branch`도, 보관 기간을 바꿨다면 `--log-retention-days`도) |
| 종료 신호 | 실행 중에 표시. 실수 방지로 한 번 누르면 붉게 바뀌고 4초 안에 한 번 더 눌러야 같은 엔진에 `stop`을 전달하며, 현재 회차를 마친 뒤 종료 |
| 종료 | 종료 신호를 보낸 뒤 표시. 확인 모달을 거쳐 즉시 강제 종료. Windows는 `taskkill /T /F`로 하위 `claude`까지 종료하고, commit 전 변경은 working tree에 남음 |

- 모델(Fable·Opus·Sonnet·Haiku)과 Effort(low~max, 단계가 오를수록 커지는 파형)는 실행 중에도 바꿀 수 있습니다. 바꾸면 엔진에 `set`으로 전달되고(Effort는 단계를 고를 때 한 번), 진행 중인 회차는 그대로 끝난 뒤 **다음 회차부터** 적용됩니다. 기다리는 값이 있으면 지금 문장 아래에 "적용 대기"로 표시되고, 회차 기록에는 회차마다 쓴 값이 남습니다. 종료 요청 후에는 바꿀 수 없습니다. 모델 알약은 기본으로 각 모델의 **최신 버전**(별칭)을 쓰고, 설정 패널의 **모델 버전**에서 Fable·Opus·Sonnet·Haiku 계열마다 특정 버전(예: Opus 4.8)을 고정할 수 있습니다. 버전 목록은 선택한 계정의 로그인 토큰으로 Anthropic 공식 모델 목록(`api.anthropic.com/v1/models`)에서 받아 와 새 모델이 나오면 앱을 고치지 않아도 목록에 따라옵니다(1시간 보관, 못 받으면 최신 버전만 고를 수 있음). 고정한 버전은 설정 범위(전역 또는 이 프로젝트)에 저장되고 실행 중에는 바꿀 수 없으며, 고정하면 그 모델을 시작·변경할 때 엔진에 모델 ID(`claude-opus-4-8` 등)로 전달됩니다. 종료 시각·정책·작업은 실행 중에 바꿀 수 없어 자물쇠와 함께 잠기고, 작업 칸은 실행 중에는 잠긴 작업 요약 한 줄로 바뀝니다.
- 화면은 시작 전·실행 중·마친 뒤 세 가지입니다. 시작 전에는 인사와 할 일 안내를, 실행 중에는 Claude가 지금 하는 일을 큰 문장 하나로 보여주고 지난 문장 셋은 위로 올라가며 흐려집니다. 문장 앞의 작은 칩은 그 문장 전에 부른 도구(Read·Edit·Bash 등)입니다. Claude가 문장 없이 도구만 부르는 동안에는 앱이 "… 파일을 차근차근 읽어 보고 있어요"처럼 도구에 맞는 문장을 지어 보여주고, 사용량 한도·재시도 대기나 종료 신호 뒤에는 기다리는 이유를 들려줍니다. Claude가 확인한 수치 변화(`성과:` 줄)는 가장 최근 것을 크게 보여주고, 그 아래에 부른 도구 수, 읽어 본 파일·고친 파일 수(같은 파일은 한 번), 남긴 커밋 수와 바뀐 줄 수가 쌓입니다. 위쪽 진행선은 시작부터 종료 예정 시각까지에 회차 구간·커밋·지금 위치를 찍습니다. 실행을 마치면 인사와 종료 이유, 성과, 회차별 커밋을 정리해 보여주고 다른 프로젝트를 고르면 시작 전 화면으로 돌아갑니다.
- 지금 문장 옆이나 마친 화면의 **전체 기록**, 설정 패널의 **전체 기록 보기**를 누르면 전체 로그(최근 3000줄 유지, 따라가기·지우기)와 회차 기록이 아래에서 펼쳐집니다. 회차·남은 시간·종료 예정 시각·회차별 결과·커밋·도구 호출은 로그 줄에서 읽습니다.
- 시작 전 화면의 인사 아래에는 **지난 실행**이 최근 3개까지 보입니다(어제 23:15 · 1시간 28분 · 정상 종료처럼 시작 시각·걸린 시간·종료 상태와 회차·커밋 수). 항목이나 **전체 보기**(설정 패널의 **지난 실행 보기**도 같음)를 누르면 프로젝트의 지난 실행 전체 목록이 시트로 열리고, 항목을 고르면 그날의 작업이 채팅처럼 이어집니다. 회차 시작, Claude의 문장(앞서 부른 도구는 칩으로), 성과, 커밋, 회차 결과, 사용량 한도 대기, 종료가 시간 순으로 나오고 위쪽에 종료 이유·성과·리포트 열기·원본 로그 열기가 있습니다. 기록은 프로젝트의 `.autopilot/progress/<날짜>/autopilot_*.log` 파일을 그대로 읽으므로 앱을 껐다 켜도, 다음 날에도 볼 수 있고 보관 기간(기본 30일)이 지나면 사라집니다. 로그가 비었거나 깨졌거나 끝맺음 줄 없이 끊겼어도(앱·PC가 꺼졌거나 강제 종료된 경우) 목록에서 빠지지 않고 `내용 없음`·`끝맺음 없음`·`읽을 수 없음`으로 표시하며 읽을 수 있는 부분만 보여줍니다. 아주 큰 로그는 끝부분만 읽고 알려줍니다. 상세 화면의 **기록 삭제**는 확인을 받은 뒤 그 실행의 로그와 리포트만 지우고(되돌릴 수 없음, 커밋·진행 기록·다른 실행은 그대로, 진행 중인 실행은 지울 수 없음) 날짜 폴더가 비면 폴더도 지웁니다.
- 작업은 긴 텍스트라 인자로 넘기지 않고 앱 데이터 폴더의 `tasks.md`에 써서 엔진이 시작할 때 한 번 읽게 합니다. 엔진은 이를 매 회차 프롬프트에 넣습니다.
- 진행 기록(`AUTOPILOT_PROGRESS.md`)은 프로젝트가 아니라 `%APPDATA%\AutoPilot\projects\` 아래에 쌓여 같은 프로젝트의 다음 실행이 이어받습니다. 이어갈 내용을 버리고 새로 시작하려면 설정 패널의 **진행 기록 초기화**를 누릅니다(확인 후 원본을 프로젝트의 `.autopilot/progress/`에 보관하고 초기화, 실행 중에는 사용할 수 없음).
- 리포트 HTML은 자동으로 열지 않고 설정 패널의 **리포트 열기**로 엽니다. 시작한 프로젝트의 `.autopilot/progress/` 안에 있는 `report_*.html`만 열고, 엔진이 알려준 경로라도 그 밖의 파일은 열지 않습니다.
- 설정 패널의 **사용량 한도**에서 "대기한 시간만큼 종료 시각 연장"을 켜면(기본 꺼짐, 고른 설정 범위에 바로 저장, 실행 중에는 잠김) 한도 대기로 쓴 시간만큼 종료 예정 시각이 늦춰지고 시계도 따라 바뀝니다. 바로 아래 **연장 상한**(제한 없음 기본, 1·3·6·12·24시간)을 고르면 한 번의 실행에서 늘리는 시간의 합이 그 안으로 묶여, 주간 한도에 걸려도 종료 시각이 며칠씩 밀리지 않습니다. 상한을 다 쓴 뒤의 대기는 종료 시각을 늘리지 않고, 시간이 모자라면 그 이유로 끝납니다.
- 설정의 **로그 보관**에서 지난 실행의 로그·리포트를 보관할 기간(7·14·30·90·180일, 기본 30일, 프로젝트별로도 정함)과 이 프로젝트의 지난 기록이 지금 차지하는 용량을 확인합니다. 보관 기간이 지난 기록은 실행을 시작할 때 지워지고, **보관 기간이 지난 기록 지금 지우기**로 바로 지울 수도 있습니다(확인을 받고, 진행 중인 실행의 로그·커밋·진행 기록은 건드리지 않음).
- 설정의 **Git**에서 AutoPilot이 만드는 커밋 메시지 앞의 **커밋 접두어**(기본 `[ap]`)와 작업할 **작업 브랜치**(기본 `ai/autopilot`)를 바꿀 수 있습니다. 팀의 커밋 규칙에 맞추거나 프로젝트마다 다르게 둘 수 있도록 프로젝트별로도 정합니다(Enter나 입력 칸을 벗어날 때 저장, 올바르지 않으면 이유를 보여줌, 실행 중에는 잠김). 접두어는 1~20자이고 앞뒤 공백과 백틱은 쓸 수 없으며, 브랜치는 영문·숫자·`._-/`로 쓰고 AI가 기본 브랜치에 직접 커밋하지 않도록 `main`·`master`는 쓸 수 없습니다. 엔진이 브랜치를 직접 만들지는 않고, 세션이 지침에 따라 그 브랜치로 전환하거나 `main`에서 분기해 만듭니다.

- 화면은 흰 바탕 한 벌이고, 지금 진행 중인 것(상태 점·진행선·캐럿·성과 숫자)에만 파란색을 씁니다. Windows의 동작 줄이기 설정을 켜면 미끄러지거나 커지는 애니메이션은 멈추고, 문장이 쓸리듯 드러나는 효과와 캐럿 깜빡임처럼 자리가 바뀌지 않는 표시만 남습니다.
- 앱은 하나만 실행됩니다. 이미 실행 중일 때 다시 켜면 새 창 없이 기존 창이 앞으로 나옵니다.
- 앱을 닫았다 켠 사이에도 엔진이 살아 있어 선택한 프로젝트에서 실행 중이면, 앱을 켜거나 창에 포커스를 줄 때 자동으로 연결합니다. 연결하면 로그 파일을 처음부터 읽어 진행 상황을 복원하고 이어서 따라가며(지난 회차의 시각은 알 수 없습니다), 종료 신호 · 모델 변경 · 강제 종료도 같은 방식으로 쓸 수 있습니다. 연결한 엔진은 앱이 소유하지 않으므로 창을 닫아도 계속 실행되고, 종료 코드는 알 수 없어 로그의 종료 사유만 표시합니다.
- 앱이 시작한 엔진이 실행 중이거나 설정의 **시스템 > 닫아도 트레이에서 계속 켜 두기**를 켜 두면 창을 닫아도 트레이로 숨기기만 하고 엔진은 계속 돕니다(트레이 아이콘을 누르면 창이 다시 열립니다). 트레이 메뉴의 **종료**는 확인 후 엔진을 강제 종료하고 앱을 닫습니다. 둘 다 아니거나 연결한 엔진이면 창을 닫을 때 앱이 그대로 종료됩니다.
- 설정의 **시스템 > 실행이 끝난 뒤**를 **PC 절전**이나 **PC 종료**로 두면(기본 **아무것도 안 함**), 앱이 시작한 실행이 스스로 끝났을 때(종료 시각 도달·작업 완료·실패 중단) 창을 띄워 알리고 1분 동안 기다렸다가 PC를 절전·종료합니다. 그 안에 **취소**하거나 **지금 절전·종료**를 누를 수 있습니다. 직접 종료 신호를 보냈거나 강제 종료했거나 연결한 엔진이 끝난 경우에는 하지 않고, 새 실행이 시작되면 기다림을 취소합니다. 종료로 바꿀 때는 확인을 받고, 이 설정은 설정 파일 내보내기·가져오기에 담기지 않으며 기본값으로 되돌리면 꺼집니다. 앱이 그 전에 종료되면 실행하지 않습니다.
- 설정의 **시스템 > 실행 중 절전 방지**에서 실행하는 동안 PC가 잠들지 않게 막을지 고릅니다(**항상**이 기본, **전원 연결 때만**은 노트북이 배터리로 돌 때 풀고 전원을 꽂으면 다시 막음, **하지 않음**). 화면은 꺼져도 되고 앱 일시 중단만 막습니다.
- 설정의 **시스템 > 새 버전 확인**을 끄면(기본 켬) 앱이 새 버전을 조회하는 네트워크 요청(앱을 켤 때와 6시간마다 GitHub 릴리스 조회)을 하지 않고 헤더의 새 버전 칩도 숨깁니다. 켜면 바로 확인합니다.
- 설정의 **시스템 > 로그인하면 자동으로 켜기**를 켜면 컴퓨터에 로그인할 때 창 없이 트레이로만 켜집니다(Windows 시작 프로그램·macOS 로그인 항목·Linux 자동 시작). 켜면 트레이 상주도 함께 켜지고, 설치한 앱에서만 켤 수 있습니다.
- 엔진이 도는 동안(연결한 엔진 포함) `powerSaveBlocker`로 PC 절전(앱 일시 중단)을 막습니다. 화면은 꺼져도 됩니다.
- 종료·실패·사용량 한도 대기로 바뀌거나 예약이 시작되면 창에 포커스가 없을 때 알림을 띄우고(누르면 창을 엽니다, 직접 강제 종료한 경우는 제외), 설정 패널의 **알림**에서 종류별(종료·실패·한도 대기·예약)로 끄거나 창을 보고 있을 때도 받게 할 수 있습니다(기본은 모두 켜고 창을 보고 있을 때는 끔). 작업표시줄 아이콘에 종료 시각까지의 진행률을 보여줍니다(종료 신호·재시도·한도 대기 중에는 일시 중지 색, 종료 시각을 모르면 진행 중 표시).
- VS Code 등이 `ELECTRON_RUN_AS_NODE=1`을 설정한 셸에서는 해제한 뒤 `npm start`·`npm test`를 실행하세요. (앱이 엔진을 띄울 때는 앱이 직접 지정합니다.)

`npm run test:desktop`은 가짜 CLI로 시작·종료 신호·강제 종료·로그 해석을 확인합니다. 엔진 자체의 검증은 [CLAUDE.md](../CLAUDE.md)의 개발 명령(`test:cli`)을 참고하세요.
