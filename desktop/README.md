# AutoPilot Desktop

Node.js 22 이상과 npm이 필요합니다. 저장소 루트에서 실행하세요.

```sh
npm install
npm start
```

| 명령 | 동작 |
| --- | --- |
| `npm start` | Electron 앱 실행 |
| `npm run dev` | 개발자 도구를 함께 열어 실행 |
| `npm test` | Electron 창, preload 연결, 로컬 HTML 로드, 번들 엔진 실행(`ELECTRON_RUN_AS_NODE`) 확인 후 자동 종료 (실행 엔진은 시작하지 않음) |
| `npm run test:desktop` | 가짜 CLI로 엔진 제어(시작·종료 신호·강제 종료·로그 해석·다시 연결)와 허용 값 일치, 프로젝트·경로 검사, 화면 문장·진행선 계산 확인 |
| `npm run build` | Windows x64 앱 폴더 생성 (`dist/win-unpacked/AutoPilot.exe`) |
| `npm run dist` | Windows x64 설치형 · 포터블 EXE 생성 (`dist/AutoPilot-Setup-<버전>-x64.exe`, `dist/AutoPilot-Portable-<버전>-x64.exe`) |

Windows에서 빌드합니다. 최초 설치와 패키징에는 Electron 및 패키징 도구 다운로드를 위한 인터넷 연결이 필요합니다. 배포 EXE는 코드 서명하지 않으므로 Windows에서 게시자 경고가 표시될 수 있습니다.

`desktop/main.cjs`는 앱 창과 보안 설정을, `systemIntegration.cjs`는 트레이·절전 방지·알림·작업표시줄 진행을, `autopilotRunner.cjs`·`autopilotIpc.cjs`·`projectFiles.cjs`·`preload.cjs`는 엔진 제어와 연결을, `viewFormat.js`·`index.html`·`desktop/ui`는 대시보드 화면을 담당합니다(`viewFormat.js`는 화면에 의존하지 않는 표시용 함수라 `npm run test:desktop`이 따로 검증합니다). 화면은 React 19로 만들어 esbuild가 `desktop/bundle/`로 묶고(`npm run build:ui`), 별도 웹 서버는 두지 않습니다. 서체는 `desktop/fonts/`의 Pretendard(SIL OFL 1.1, `Pretendard-LICENSE.txt` 동봉)를 앱에 넣어 오프라인에서도 같게 보입니다.

엔진(`autopilot/`)은 앱에 포함됩니다. 앱은 자기 실행 파일을 `ELECTRON_RUN_AS_NODE=1`로 실행해 엔진 스크립트를 자식 프로세스로 띄웁니다(개발 중에는 저장소의 `autopilot/core/autopilot_loop.js`, 패키지에서는 `resources/engine/core/autopilot_loop.js`). 별도 엔진 파일을 연결할 필요가 없습니다.

## 대시보드 사용법

1. 왼쪽 레일 아래쪽의 설정(톱니) 패널의 **대상 프로젝트**에서 **폴더 선택**으로 대상 프로젝트를 고릅니다. `.git`이 있는 Git 저장소의 루트 폴더만 받습니다. 고르기 전에는 작업 칸 위에 안내와 **폴더 선택** 버튼이 표시되고 시작 버튼이 잠깁니다. 고른 프로젝트 이름은 시작 화면 인사말("오늘 밤에는 ○○에 무엇을 해 둘까요?")에 들어갑니다.
2. 화면 아래 카드의 칸에 처리할 작업을 한 줄에 하나씩 적고(칸 높이는 고정이고 넘치면 칸 안에서 스크롤), 카드 아래쪽 알약 버튼으로 Claude·Codex(모델과 노력·추론)·개선 정책·종료 시각을 정합니다. 정책·종료 시각은 누르면 고르는 창이 뜨고(종료 시각은 3시간 뒤·내일 07:00·주말 내내·일주일 바로가기, 오늘부터 7일 뒤까지의 날짜 띠, 끝낼 시각 칸으로 고르고 남은 시간이 함께 보임. 7일 뒤까지 정할 수 있음), Claude·Codex 알약은 AI마다 하나씩 늘 보이고(신규 개발에서 단계를 어떻게 고르든 같음), 누르면 모델 목록과 노력(Claude)·추론(Codex) 슬라이드가 한 창에 뜹니다. 슬라이드는 Low·Medium·High·Extra High·Max 다섯 단계이고 단계마다 설명이 바뀌며 Max에서는 붉게 바뀝니다. Claude에는 계열(최신 버전을 따라감) 아래에 고를 수 있는 버전이 이어지고(버전을 고르면 그 계열을 그 버전으로 고정), Codex에는 Codex가 알려 준 모델이 있고(기본 gpt-6.1-sol) 추론은 슬라이드로 정합니다(기본 High). Codex 설정 파일은 따르지 않고 늘 값을 지정해 넘깁니다. 유지 보수에서는 어느 쪽이 작업할지를 창 맨 아래 **이 AI로 작업하기** 스위치로 고르고(알약 끝에 **메인**이 붙음), 신규 개발에서는 단계마다 메인을 정하며 창 맨 아래에 그 AI가 메인인 단계가 보입니다. Codex가 설치·로그인돼 있지 않으면 Codex 창에 이유가 보입니다. 개선 정책은 설정 패널에서도 고를 수 있습니다. 종료 시각을 비우면 07:00이고, 정책은 자율개선이 기본입니다. **지시개선은 작업이 있어야** 시작합니다. 시작 화면 오른쪽 위의 **유지 보수 | 신규 개발**로 작업 모드를 고릅니다. 신규 개발이면 작업 칸에 만들고 싶은 것을 적고(기획은 이 내용이 있어야 시작), 단계 카드(기획·디자인·개발·테스트/QA·보안검토)의 아래 문장(예: "기획은 [Codex가 메인]이고, [Claude와 협의해서] 진행하고, 끝나면 멈추고 못 맞춘 쟁점만 고를게요.")에서 단계마다 메인 AI(Claude·Codex)·보조 AI(메인의 반대쪽 AI를 붙일지)·끝나면 멈출지·디자인 산출물·테스트/QA·보안검토가 실패하면 개발로 몇 번까지 되돌릴지(숫자로 정함)를 고르고(모델·노력·추론은 문장이 아니라 입력창의 알약에서 정함), 정책 알약 대신 **허용** 알약에서 이번 실행에 풀어 줄 정책(새 라이브러리·큰 구조·외부 API 호출 코드·외부 서비스로 코드 보내기)을 위험도(낮음·보통·높음)와 허용해도 지키는 선을 보며 체크합니다. 이어서 할 단계가 있으면 카드와 시작 버튼(예: **디자인 시작**)이 그 단계부터 보여 줍니다.
3. **시작**을 누릅니다. 프로젝트는 고르는 즉시, 나머지(작업·종료 시각·정책·모델·노력·사용량 한도 연장)는 시작할 때 그 프로젝트의 설정에 기억되어(전역 값과 다른 것만) 같은 프로젝트를 다시 열면 복원됩니다. 프로젝트에 기억된 값이 없으면 설정 패널의 전역 값을 씁니다(아래 **전역 설정과 프로젝트 설정**). 실행 중 모델·Effort 변경이 엔진에 전달되면 그 값도 기억됩니다.

카드 오른쪽 아래 버튼 하나가 상태에 따라 바뀝니다.

| 버튼 | 동작 |
| --- | --- |
| 시작 | 엔진을 `--project <프로젝트> --no-open --tasks-file <작업 파일> --policy ... --model ... --effort ...`로 자식 프로세스 실행 (종료 시각을 적었다면 `--end-time`, 설정에서 켰다면 `--extend-on-limit`과, 연장 상한을 정했다면 `--max-extend-minutes`도, 커밋 접두어·작업 브랜치를 바꿨다면 `--commit-prefix`·`--branch`도, 보관 기간을 바꿨다면 `--log-retention-days`도, 연결 저장소가 있다면 저장소마다 `--link-project`도) |
| 종료 신호 | 실행 중에 표시. 실수 방지로 한 번 누르면 붉게 바뀌고 4초 안에 한 번 더 눌러야 같은 엔진에 `stop`을 전달하며, 현재 회차를 마친 뒤 종료 |
| 종료 | 종료 신호를 보낸 뒤 표시. 확인 모달을 거쳐 즉시 강제 종료. Windows는 `taskkill /T /F`로 하위 `claude`까지 종료하고, commit 전 변경은 working tree에 남음 |

- 모델(Fable·Opus·Sonnet·Haiku)과 노력(low~max, 단계가 오를수록 커지는 파형)·Codex의 모델과 추론은 실행 중에도 바꿀 수 있습니다. 바꾸면 엔진에 `set`으로 전달되고(노력은 슬라이드를 놓을 때 한 번), 진행 중인 회차는 그대로 끝난 뒤 **다음 회차부터** 적용됩니다. 기다리는 값이 있으면 지금 문장 아래에 "적용 대기"로 표시되고, 회차 기록에는 회차마다 쓴 값이 남습니다. 종료 요청 후에는 바꿀 수 없습니다. 모델 알약은 기본으로 각 모델의 **최신 버전**(별칭)을 쓰고, 설정 패널의 **모델 버전**에서 Fable·Opus·Sonnet·Haiku 계열마다 특정 버전(예: Opus 4.8)을 고정할 수 있습니다. 버전 목록은 선택한 계정의 로그인 토큰으로 Anthropic 공식 모델 목록(`api.anthropic.com/v1/models`)에서 받아 와 새 모델이 나오면 앱을 고치지 않아도 목록에 따라옵니다(1시간 보관, 못 받으면 최신 버전만 고를 수 있음). 고정한 버전은 설정 범위(전역 또는 이 프로젝트)에 저장되고 실행 중에는 바꿀 수 없으며, 고정하면 그 모델을 시작·변경할 때 엔진에 모델 ID(`claude-opus-4-8` 등)로 전달됩니다. 종료 시각·정책·작업은 실행 중에 바꿀 수 없어 자물쇠와 함께 잠기고, 작업 칸은 실행 중에는 잠긴 작업 요약 한 줄로 바뀝니다.
- 화면은 시작 전·실행 중·마친 뒤 세 가지입니다. 시작 전에는 인사와 할 일 안내를, 실행 중에는 Claude가 지금 하는 일을 큰 문장 하나로 보여주고 지난 문장 셋은 위로 올라가며 흐려집니다. 문장 앞의 작은 칩은 그 문장 전에 부른 도구(Read·Edit·Bash 등)입니다. Claude가 문장 없이 도구만 부르는 동안에는 앱이 "… 파일을 차근차근 읽어 보고 있어요"처럼 도구에 맞는 문장을 지어 보여주고, 사용량 한도·재시도 대기나 종료 신호 뒤에는 기다리는 이유를 들려줍니다. Claude가 확인한 수치 변화(`성과:` 줄)는 가장 최근 것을 크게 보여주고, 그 아래에 부른 도구 수, 읽어 본 파일·고친 파일 수(같은 파일은 한 번), 남긴 커밋 수와 바뀐 줄 수가 쌓입니다. 이 숫자와 남긴 커밋, 회차 목록(신규 개발은 기획서·디자인 같은 단계 문서, 누르면 열림)은 오른쪽 카드에 모입니다(창이 좁으면 숫자만 이야기 아래 한 줄로). 위쪽 진행선은 시작부터 종료 예정 시각까지에 회차 구간·커밋·지금 위치를 찍고, 하루를 넘기는 실행은 끝나는 날짜도 보여줍니다. 신규 개발은 프로젝트 이름 아래 단계 카드에 지금 단계와 지난 단계(확인함)가 보입니다. 실행을 마치면 인사와 종료 이유, 성과, 회차별 커밋을 정리해 보여주고 다른 프로젝트를 고르면 시작 전 화면으로 돌아갑니다. 신규 개발을 모두 마쳤으면 **유지 보수로 이어 다듬기**, 테스트/QA에서 멈췄으면 **qa.md 열기**가 함께 나옵니다.
- **확인 기다림**: 신규 개발이 "끝나면 **멈추고 확인 받을게요**"로 둔 단계(기획·디자인)를 마치면 실행이 멈추고 산출물(`docs/autopilot/plan.md`, 디자인 문서나 `design/` 폴더 목록)을 미리 보여 줍니다. **확인하고 디자인 시작**(또는 개발 시작)을 누르면 승인하고 바로 다음 단계를 시작하고, 고칠 점을 적고 **이 내용으로 기획 다시 하기**를 누르면 그 내용을 수정 요청으로 넘겨 같은 단계를 다시 합니다(작업 칸에 적어 둔 만들 것은 그대로 남습니다). 전체 문서는 **기획서 전체 열기**로 기본 앱에서 엽니다. 단계 카드의 기획·디자인 문장에서 보조로 **<보조>가 따로 안을 내서**를 고르면 메인의 반대쪽 AI도 따로 안을 내고, 그 단계는 끝나면 늘 멈춰 두 안을 나란히 보여 줍니다(보조가 Codex면 이 PC에 Codex가 설치·로그인돼 있어야 하고 고르면 외부 서비스로 보내기가 켜집니다. Codex가 메인이고 Claude가 보조면 켜지 않습니다). 카드의 **보조** 줄에서 **서로 검토도 해요**를 고르면 서로의 안에 대한 짧은 검토가 각 안 아래에 붙습니다. 마음에 드는 안의 **이 안으로 … 시작**을 누르면 그 안으로 확정하고 다음 단계를 시작합니다. **<보조>와 협의해서**를 고르면 두 AI가 각자 안을 낸 뒤 둘 다 반대도 더 개선할 점도 없다고 할 때까지 주고받으며(실행 화면에 말풍선으로 실시간으로 보입니다) 합의안을 만들고, 주고받는 횟수의 상한은 **보조** 줄의 **협의는 N번까지**에서 정합니다(기본 8번, 1~20번이고 보조를 쓰는 모든 단계가 같은 값을 씁니다), 확인 화면에서는 합의안과 협의 기록을 보고 끝까지 못 맞춘 쟁점만 쟁점마다 Claude 쪽 · Codex 쪽 중에서 골라 **이대로 … 시작**을 누릅니다. 보조를 쓸 수 없거나 실패하면 건너뛰고 메인의 안으로(협의 중에 실패하면 두 안 나란히 보기로) 진행합니다. Codex가 쓸 모델과 추론은 입력창의 Codex 알약에서 고릅니다(위 2번). 협의에서 Claude의 발언은 입력창에서 고른 Effort를 따릅니다. 산출물 미리보기는 마크다운(표·중첩 목록·인용·체크 목록·굵게·코드)을 그대로 그리고 칸 안에서 스크롤하며, 제목이 여럿이면 제목마다 접고 펼 수 있습니다(모두 접기). 협의한 단계는 합의안과 협의 기록을 탭으로 오가며, 협의 기록은 카카오톡처럼 말풍선과 동의·반대·바꾼 점으로 보여 줍니다. 실행 중 협의 대화의 말풍선에는 받은 시각이 붙고 긴 말은 더 보기로 펼칩니다.

- **홈**: 앱을 켜면 처음 보이는 화면이고, 레일 맨 위(로고 아래)의 **홈**으로 언제든 돌아옵니다. 열린 모든 프로젝트를 시간 순서로 보여줍니다. **이어하기**(지금)는 지금 일하는 프로젝트, 확인을 기다리는 단계, 한도나 오류로 멈춘 프로젝트(3일 안)만 모아 첫 항목은 카드로, 나머지는 한 줄로 보이고 단추를 누르면 그 프로젝트로 이동합니다(홈에서 바로 시작하지는 않습니다). **오늘 예정**(앞으로)은 오늘 시작할 예약과 한도가 리셋되면 시작할 예약을 시각 순으로, **마지막 한 일**(지난)은 열린 프로젝트 중 가장 최근에 끝난 실행 하나를 결과 문장·회차·커밋 수와 함께 보여주며 **대화 보기**와 **리포트 열기**가 있습니다. 로그인 만료와 새 버전 안내는 홈에 따로 두지 않고 화면 아래 안내 줄과 위쪽 실행 줄의 칩이 알립니다. 프로젝트가 하나도 없으면 새로 만들거나 여는 두 길과 짧은 안내가 보이고, 마지막 탭을 닫아도 홈으로 돌아옵니다.
- **새 프로젝트**: 왼쪽 레일의 **새 프로젝트**는 아직 없는 프로젝트를 만듭니다. 만들고 싶은 것을 한두 줄 적고(예시 칩으로 채워도 됨) **초안 만들기**를 누르면 Claude나 Codex(**AI 추천** 줄이나 **초안 AI**에서 고름. 둘은 같은 선택이며 직접 고른 AI는 다음에 열 때도 이어집니다)가 이름·한 줄 요약·사용자·기능·이번에 하지 않을 것·기술 스택을 채웁니다(Claude는 10초, Codex는 30초쯤, 새 탭의 기본 계정 사용량을 조금 씀). 다듬기 화면에서 칩을 눌러 넣고 빼며(회색은 추천), 오른쪽에서 docs/autopilot/brief.md 초안을 바로 봅니다. **만들기**는 만들 위치(마지막으로 만든 위치, 처음엔 문서 폴더, **바꾸기**로 변경)에 폴더와 Git 저장소(main)를 만들고 brief.md를 첫 커밋으로 남긴 뒤 신규 개발 탭으로 엽니다. 같은 이름의 폴더가 있고 비어 있지 않으면 만들지 않습니다. Git 작성자가 설정돼 있지 않으면 이름·이메일을 받아 그 저장소에만 저장합니다. 초안이 실패하면 적은 내용으로 직접 채우면 되고, **직접 다 쓸게요**로 AI 없이 만들 수도 있습니다. 예시 칩 아래 **AI 추천**의 **추천 예시 받기**는 기본 예시는 그대로 두고 고른 AI(Claude Haiku 또는 Codex)에게 새 예시만 받으며, AI마다 받은 목록을 따로 기억하고 지금 칸에 들어간 예시는 눌린 칩으로 보입니다. 선택한 AI에 로그인되어 있지 않거나(Codex는 설치도) 사용량 한도를 다 썼으면 **추천 예시 받기**와 **초안 만들기**가 잠기고 이유(한도는 리셋 시각까지)와 **로그인하기** · **<다른 AI>로 바꾸기** · **다시 확인**이 초안 만들기 줄 위에 나옵니다. 직접 고르기 전에는 쓸 수 있는 AI로 알아서 시작합니다.
- **프로젝트 탭**: 왼쪽 레일의 **프로젝트 열기**로 폴더를 골라 프로젝트를 더 열면 프로젝트마다 AutoPilot을 따로 돌릴 수 있습니다(8개까지, 앱을 다시 켜도 유지). 프로젝트마다 작업·종료 시각·정책·모델·Effort·**계정**이 따로이고, 실행 중인 프로젝트에는 도는 고리가, 보고 있는 프로젝트에는 모드와 신규 개발 단계가 한 줄로 보입니다. 위쪽 실행 줄에는 모든 프로젝트 중 실행 중인 것이 모여 보입니다. 같은 프로젝트는 한 탭만 열 수 있어서, 이미 열린 프로젝트를 다시 열면 새 탭 대신 그 탭으로 이동합니다. 실행 중인 탭은 닫을 수 없고(먼저 종료), 예약이 있는 프로젝트의 탭을 닫으면 다시 열 때까지 그 예약이 실행되지 않는다고 확인합니다. 탭을 옮겨도 아직 시작하지 않고 쓰던 작업 문구는 돌아오면 그대로 있습니다. 설정 패널의 **폴더 선택**은 지금 탭의 프로젝트를 바꿉니다. 여러 탭을 동시에 돌리면 같은 계정의 사용량 한도는 함께 줄어듭니다(탭마다 계정을 다르게 고를 수 있습니다). 전역 예약은 그때 보고 있는 탭에서, 프로젝트 예약은 그 프로젝트의 탭에서 실행됩니다. PC 절전 방지·작업표시줄 진행률·알림은 모든 탭을 함께 보고, 끝난 뒤 PC 절전·종료는 마지막으로 스스로 끝나는 탭이 정합니다. 계정 추가·제거·데이터 폴더 변경과 설정 가져오기·기본값 복원은 어느 탭이든 실행 중이면 할 수 없습니다. 프로젝트를 바꿔도 단계 상태는 유지되며, 다른 프로젝트가 확인을 기다리고 있으면 레일의 그 프로젝트 줄에 "기획 확인을 기다려요"처럼 보입니다.

- **로그아웃**: 한도 패널 각 열의 계정 단추 안에 있는 **로그아웃**이 선택한 계정의 로그인 정보만 지웁니다(`claude auth logout`·`codex logout`). 계정은 목록에 남아 있어 다시 로그인하면 바로 쓸 수 있고, **이 계정 제거**와 달리 계정 폴더·이름은 지우지 않습니다. 기본 계정도 로그아웃할 수 있으며, 실행 중에는 막힙니다.
- **Codex 계정과 한도**: 한도 패널의 오른쪽 열이 Codex입니다. Codex도 Claude처럼 계정을 여러 개 추가하고(계정마다 앱 데이터 폴더 `codex-accounts/`에 로그인 정보를 따로 두는 `CODEX_HOME`을 씁니다) 탭마다 다른 계정을 고를 수 있고, 시작하면 고른 계정으로 엔진이 실행됩니다(`--codex-home`. 기본 계정은 환경의 `CODEX_HOME`·`~/.codex`를 그대로 씁니다). 로그인은 `codex login`(브라우저)로 진행합니다. 한도는 Codex가 세션 기록(`sessions/.../rollout-*.jsonl`의 `token_count`)에 남긴 마지막 값을 읽어 5시간·주간 한도처럼 막대로 보여 줍니다. 그래서 그 계정으로 Codex를 쓴 뒤에 갱신되고, 기준 시각이 마지막으로 쓴 때이며, 아직 쓴 적이 없으면 안내만 보입니다. 리셋 시각이 지난 값은 0%로 봅니다. 한도에 걸려도 다른 계정으로 자동 전환하지는 않습니다.
- **로그인 만료 안내**: Claude Code의 저장된 로그인에는 만료일이 있어 갱신만으로 계속 유지된다고 볼 수 없습니다. 앱은 `.credentials.json`의 만료 시각(`refreshTokenExpiresAt`, 시각 값만 읽고 토큰은 저장하지 않습니다)을 한도 패널 Claude 열에 `로그인 만료 11월 13일 15:52 · 29일 3시간 후`처럼 보여줍니다. 만료 3일 전부터(Claude Code의 경고와 같은 시점) 컴포저 위에 안내 줄이 뜨고, 한도 패널에도 **다시 로그인** 버튼이 나옵니다. 누르면 이미 아는 이메일을 로그인 페이지에 미리 채워(`claude auth login --email`) 시작하므로 인증 코드만 입력하면 됩니다. 만료된 뒤에는 만료됐다는 안내가 뜹니다. 앱이 토큰을 직접 갱신하거나 보관하지 않으며(갱신은 Claude Code가 합니다) macOS는 위와 같은 이유로 만료 시각을 읽지 못해 보이지 않습니다. 개발 중에는 `npm run dev -- --debug-login-expiry=2d`처럼 만료 시각을 임시로 바꿔 화면을 볼 수 있습니다(`30m`·`5h`·`2d` 형식, 이미 만료된 상태는 `-1m`. 패키지 앱에서는 무시합니다).
- **플랫폼**: 배포 파일은 Windows(설치형 · 포터블), macOS(dmg · zip), Linux(AppImage · deb)이고 계정 기능은 Windows·Linux·macOS에서 같은 방식으로 동작하도록 만들었습니다. 로그인은 모든 플랫폼에서 `claude auth login`을 쓰고 로그인 여부는 `claude auth status`로 확인합니다. 사용량·프로필 조회는 Claude Code가 로그인 정보를 둔 곳에서 읽습니다. Windows·Linux는 설정 폴더의 `.credentials.json`, macOS는 키체인이고, 키체인을 읽지 못하면(접근 거부) 안내를 표시하고 한 시간 동안 다시 묻지 않습니다. `claude` 실행 파일은 `PATH`에서 찾습니다. Finder·Dock·데스크톱 아이콘으로 연 macOS·Linux 앱은 터미널의 `PATH`를 받지 못하므로, 앱이 켜질 때 로그인 셸의 `PATH`와 `~/.local/bin`·`~/.claude/local`·Homebrew 같은 흔한 설치 위치를 합칩니다.
- 창은 가로형(기본 1160×800)이고 왼쪽 레일과 위쪽 실행 줄은 앱이 직접 그립니다. 레일의 오른쪽 경계를 끌면 너비를 200~360px로 바꿀 수 있고(두 번 클릭하면 기본 224px), 더 좁히면 아이콘만 남은 띠로 접히며, 바꾼 너비는 앱을 다시 켜도 남습니다. 창이 좁아도(960px 미만) 레일이 같은 띠로 접힙니다. 실행 줄이나 레일의 빈 곳을 끌어 창을 옮기고 두 번 클릭하면 최대화하며, 실행 줄 오른쪽 버튼으로 최소화·최대화·닫기를 합니다(닫기는 실행 중이면 아래 확인을 거칩니다). 설정 패널의 **시스템 > 화면 테마**에서 밝게·어둡게·시스템 설정 따라가기를 고릅니다. 프로필·설정 패널은 같은 자리에 뜨므로 하나를 열면 다른 하나가 닫히고, Esc나 패널 밖을 눌러 닫습니다.
- 화면은 흰 바탕 한 벌이고, 지금 진행 중인 것(상태 점·진행선·캐럿·성과 숫자)에만 파란색을 씁니다. Windows의 동작 줄이기 설정을 켜면 미끄러지거나 커지는 애니메이션은 멈추고, 문장이 쓸리듯 드러나는 효과와 캐럿 깜빡임처럼 자리가 바뀌지 않는 표시만 남습니다.
- 앱은 하나만 실행됩니다. 이미 실행 중일 때 다시 켜면 새 창 없이 기존 창이 앞으로 나옵니다.
- 앱을 닫았다 켠 사이에도 엔진이 살아 있어 열린 탭의 프로젝트에서 실행 중이면, 앱을 켜거나 창에 포커스를 줄 때 자동으로 연결합니다. 연결하면 로그 파일을 처음부터 읽어 진행 상황을 복원하고 이어서 따라가며(지난 회차의 시각은 알 수 없습니다), 종료 신호 · 모델 변경 · 강제 종료도 같은 방식으로 쓸 수 있습니다. 연결한 엔진은 앱이 소유하지 않으므로 창을 닫아도 계속 실행되고, 종료 코드는 알 수 없어 로그의 종료 사유만 표시합니다.
- 앱이 시작한 엔진이 실행 중이거나 설정의 **시스템 > 닫아도 트레이에서 계속 켜 두기**를 켜 두면 창을 닫아도 트레이로 숨기기만 하고 엔진은 계속 돕니다(트레이 아이콘을 누르면 창이 다시 열립니다). 트레이 메뉴의 **종료**는 확인 후 엔진을 강제 종료하고 앱을 닫습니다. 둘 다 아니거나 연결한 엔진이면 창을 닫을 때 앱이 그대로 종료됩니다.
- 설정의 **시스템 > 실행이 끝난 뒤**를 **PC 절전**이나 **PC 종료**로 두면(기본 **아무것도 안 함**), 앱이 시작한 실행이 스스로 끝났을 때(종료 시각 도달·작업 완료·실패 중단) 창을 띄워 알리고 1분 동안 기다렸다가 PC를 절전·종료합니다. 그 안에 **취소**하거나 **지금 절전·종료**를 누를 수 있습니다. 직접 종료 신호를 보냈거나 강제 종료했거나 연결한 엔진이 끝난 경우에는 하지 않고, 새 실행이 시작되면 기다림을 취소합니다. 종료로 바꿀 때는 확인을 받고, 이 설정은 설정 파일 내보내기·가져오기에 담기지 않으며 기본값으로 되돌리면 꺼집니다. 앱이 그 전에 종료되면 실행하지 않습니다.
- 설정의 **시스템 > 실행 중 절전 방지**에서 실행하는 동안 PC가 잠들지 않게 막을지 고릅니다(**항상**이 기본, **전원 연결 때만**은 노트북이 배터리로 돌 때 풀고 전원을 꽂으면 다시 막음, **하지 않음**). 화면은 꺼져도 되고 앱 일시 중단만 막습니다.
- 설정의 **시스템 > 새 버전 확인**을 끄면(기본 켬) 앱이 새 버전을 조회하는 네트워크 요청(앱을 켤 때와 6시간마다 GitHub 릴리스 조회)을 하지 않고 헤더의 새 버전 칩도 숨깁니다. 켜면 바로 확인합니다.
- 설정의 **시스템 > 로그인하면 자동으로 켜기**를 켜면 컴퓨터에 로그인할 때 창 없이 트레이로만 켜집니다(Windows 시작 프로그램·macOS 로그인 항목·Linux 자동 시작). 켜면 트레이 상주도 함께 켜지고, 설치한 앱에서만 켤 수 있습니다.
- 엔진이 도는 동안(연결한 엔진 포함) `powerSaveBlocker`로 PC 절전(앱 일시 중단)을 막습니다. 화면은 꺼져도 됩니다.
- 종료·실패·사용량 한도 대기로 바뀌거나 예약이 시작되면 창에 포커스가 없을 때 알림을 띄우고(누르면 창을 엽니다, 직접 강제 종료한 경우는 제외), 설정 패널의 **알림**에서 종류별(종료·실패·한도 대기·예약)로 끄거나 창을 보고 있을 때도 받게 할 수 있습니다(기본은 모두 켜고 창을 보고 있을 때는 끔). 작업표시줄 아이콘에 종료 시각까지의 진행률을 보여줍니다(종료 신호·재시도·한도 대기 중에는 일시 중지 색, 종료 시각을 모르면 진행 중 표시). Windows에서는 일하는 동안 작업표시줄 아이콘 모서리에 파란 호가 도는 표시도 얹습니다(대기·종료 신호 중에는 빠지고, Windows가 애니메이션을 줄이게 설정돼 있으면 멈춘 그림 한 장만 보입니다).
