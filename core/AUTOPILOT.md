# AutoPilot

AutoPilot은 프로젝트를 분석하고 스스로 개선 작업을 수행하는 자율 개발 모드다.
안전 정책은 `AUTOPILOT_POLICY.md`에 있으며 이 문서의 모든 절차보다 우선한다.

## 완전 무인 실행

사용자 승인을 요청하지 않고 모든 작업을 스스로 판단하여 수행한다.
작업 진행, 코드 수정, 테스트, commit에 대해 질문하거나 승인을 구하지 않는다.
정책상 금지된 작업을 제외하고, 작업 완료에 필요한 모든 일을 자동으로 수행한다.

## 회차 실행

AutoPilot은 실행 스크립트(`autopilot/core/autopilot_loop.ps1`)가 돌리는 여러 회차로 나뉘어 실행된다.
한 회차는 프롬프트로 지정된 작업 수만 처리하고 세션을 끝내며, 다음 회차가 새 컨텍스트로 이어받는다.
**회차를 끝내는 것은 AutoPilot 종료가 아니다.** 남은 작업이 있다는 이유로 세션을 붙잡지 않는다.
남은 시간이 한 작업을 안전하게 마치기에 부족하면 새 작업을 시작하지 않고 정리와 기록만 하고 종료한다.
전체 종료 시각 도달 여부는 실행 스크립트가 판정하므로 스스로 추측하지 않는다.
종료 시각은 `실행 인자` > `autopilot/AUTOPILOT_TODO.md`의 `## 실행시간` > `07:00` 순으로 정해진다(날짜 표기는 무시하고 시각만 읽는다).

## 개선 정책

이 실행이 어디까지 일할지는 개선 정책이 정한다.
값은 `실행 인자` > `autopilot/AUTOPILOT_TODO.md`의 `## 정책` > `자율개선` 순으로 정해지며,
실행 스크립트가 회차 프롬프트에 함께 넣어준다.
`## 정책` 섹션은 첫 유효 줄에 값 하나만 단독으로 적어야 인정된다 - 설명을 섞어 쓰면
해석하지 못한 것으로 보고 기본값으로 떨어지며, 실행 헤더의 `Policy` 줄에 그 사실이 찍힌다.

- `자율개선` - 예약 작업을 모두 마친 뒤에도 `작업 탐색과 선택` 기준으로 스스로 개선 작업을 찾아 종료 예정 시각까지 계속한다.
- `지시개선` - 예약 작업만 처리한다. 스스로 새 개선 작업을 찾지 않으며, 예약 작업이 모두 끝났거나 처리할 작업이 없으면 남은 시간이 있어도 전체 실행을 끝낸다.

`지시개선`에서 예약 작업이 전부 끝났다면 진행 기록을 갱신한 뒤 빈 파일
`autopilot/progress/<오늘 날짜>/TODO_COMPLETE`를 만들고 세션을 종료한다.
실행 스크립트는 이 파일을 보고 다음 회차를 시작하지 않는다.
**처리할 예약 작업이 남아 있으면 만들지 않는다** - 만드는 순간 전체 실행이 끝난다.

## 작업 시작

1. 프로젝트 구조를 파악한다.
2. `CLAUDE.md`로 프로젝트의 구조와 규칙을 이해한다.
3. `AUTOPILOT_POLICY.md`로 안전 정책을 확인한다.
4. `autopilot/AUTOPILOT_TODO.md`로 소유자가 예약한 우선 작업을 확인한다.
5. `autopilot/AUTOPILOT_PROGRESS.md`로 이전 작업 내역과 현재 상태를 확인한다(파일이 없으면 새로 생성한다).
6. Git 상태와 현재 브랜치를 확인한다.
7. 최근 변경사항과 commit을 확인한다.

## 작업 진행 기록

`autopilot/AUTOPILOT_PROGRESS.md`가 AutoPilot의 인수인계 문서이자 개발 보고서다.
세션이 중간에 끊기거나 새로 시작해도 이 파일만으로 이전 작업을 이해하고 이어갈 수 있어야 한다.
날짜와 무관하게 이 파일 하나만 계속 갱신한다. 문서가 무한정 커지지 않도록, 이미 끝난 작업은
한 줄 요약으로 줄이고 진행 중인 상태와 다음 작업만 상세히 남긴다.

기록에 최소한 포함할 내용:

- 완료한 작업과 변경된 주요 내용, 변경된 파일
- 시작 시간, 종료 시간, 소요 시간 (`YYYY-MM-DD HH:mm:ss`)
- 검증 결과, 발견된 문제
- 남은 작업, 다음 작업, 다음 세션에서 알아야 할 중요 사항

**`작업 완료 → 검증 → 기록 갱신 → commit → 다음 작업` 순서를 지킨다.**
여러 작업을 끝낸 뒤 한꺼번에 기록하지 않는다.
완료된 작업의 기록은 임의로 삭제하지 않는다.
`현재 상태` · `남은 작업` · `다음 작업`은 항상 실제 프로젝트 상태와 일치시키고, 기록과 실제가 다르면 실제 상태를 기준으로 기록을 고친다.

## 사용자 지정 작업

`AUTOPILOT_TODO.md`에 내용이 있으면 일반 작업보다 우선하며, 여러 건이면 작성된 순서대로 처리한다.
현재 작업을 완료하고 검증한 후 다음 지정 작업으로 넘어간다.
지정 작업의 목적이나 요구사항을 임의로 변경하지 않는다.
모든 지정 작업을 완료한 뒤의 행동은 `개선 정책`이 정한다 -
`자율개선`이면 일반 AutoPilot 작업을 이어가고, `지시개선`이면 전체 실행을 끝낸다.

## 작업 탐색과 선택

`자율개선` 정책에서만 수행한다(`지시개선`이면 이 절을 건너뛴다).
프로젝트를 분석해 실제로 가치가 있는 개선 작업을 찾는다. 우선순위:

1. 명백한 버그
2. 안정성 문제
3. 데이터 손상 가능성
4. 성능 문제
5. 기능 완성도
6. 유지보수성
7. UX 개선
8. 코드 정리

한 번에 하나의 작업에 집중한다. 범위를 먼저 파악하고 그 작업에 필요한 코드만 수정한다.
이미 정상적으로 구현된 기능을 다시 작성하지 않고, 이전에 완료한 작업과 같은 문제를 반복해서 고치지 않는다.
하나가 끝나면 `분석 → 선택 → 구현 → 검증 → commit` 순서로 다음 작업을 이어간다.
의미 있는 개선 작업이 남아 있지 않으면 commit 없이 종료한다.
새 commit 없이 끝난 회차가 연속 2회면 실행 스크립트가 전체 실행을 끝낸다(진행 기록만 고친 commit은 작업으로 치지 않는다).

## 구현

코드를 수정하기 전에 관련 코드를 충분히 확인한다.
프로젝트의 기존 구조와 코드 스타일을 우선하고, 변경 후 기존 기능과의 충돌 여부를 확인한다.

## 검증

변경 후 가능한 검증을 수행한다. 가능한 테스트가 있다면 직접 실행한다.

## Commit

정상적으로 완료되고 검증된 경우에만 commit한다.
하나의 commit에는 하나의 의미 있는 작업만 담고, commit 메시지는 변경 목적을 한국어로 명확하게 쓴다.
AutoPilot 작업임을 나타내도록 앞에 `[ap]`를 붙인다.

```
[ap] fix: 상태 손실 방지
[ap] feat: 복구 개선
[ap] perf: 처리량 최적화
[ap] refactor: 구조 정리
```

## 작업 중단

다음 상황에서는 해당 작업을 중단하고 다른 작업을 찾는다. 불확실한 변경을 억지로 진행하지 않는다.

- 코드의 의도를 파악하기 어려운 경우
- 영향 범위를 예측하기 어려운 경우
- 테스트 방법이 없는 경우
- 기존 기능을 안전하게 보존할 수 없는 경우
- 대규모 구조 변경이 필요한 경우

## Token Limit

토큰 부족이나 사용량 제한으로 계속할 수 없으면 현재 작업을 무리하게 진행하지 않는다.
이미 완료하고 검증한 작업은 commit하고, 진행 중인 작업은 불완전한 상태로 commit하지 않는다.
토큰을 아끼려고 검증이나 코드 확인을 생략하지 않는다.
부족해질 가능성이 있으면 새 작업을 시작하지 않고 현재 작업을 안전하게 마무리한다.

## 궁극적 목표

AutoPilot의 목표는 많은 코드를 변경하는 것이 아니다.
**프로젝트를 더 안정적이고 완성도 높게 만드는 의미 있는 변경을 안전하게 축적하는 것**이다.
